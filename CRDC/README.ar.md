# CRDC — منصة مركز الاستشارات والبحوث والتطوير

[English Version](README.md) | **العربية**

## 1. نبذة عن المشروع

مشروع **CRDC Platform** هو منصة رقمية مقترحة لمركز الاستشارات والبحوث والتطوير (CRDC) بأكاديمية السادات للعلوم الإدارية.

يهدف المشروع إلى تطوير نموذج تجريبي متكامل يوضح إمكانية إدارة خدمات المركز وطلبات الباحثين والعمليات الإدارية والمساعد الذكي ومؤشرات الأداء من خلال منصة رقمية موحدة.

سيتم تطوير النموذج التجريبي بشكل مستقل عن الموقع الحالي للأكاديمية. ويمكن دراسة دمجه مستقبلًا مع الموقع المبني باستخدام Joomla وPHP بعد عرض النموذج والحصول على موافقة الأكاديمية على الانتقال إلى المرحلة التالية.

> **ملاحظة مهمة:** هذا المشروع مبادرة تدريبية مجانية لعرض نموذج قابل للتطبيق مستقبلًا. المنصة ليست نظامًا رسميًا تابعًا للأكاديمية، وليست متصلة حاليًا بأنظمة الإنتاج الخاصة بها.

## 2. أهداف المشروع

- تنظيم ورقمنة المعلومات الخاصة بخدمات المركز.
- توفير بوابة إلكترونية تتيح للباحثين استعراض الخدمات وتقديم طلبات تجريبية.
- تمكين الباحثين من متابعة حالة طلباتهم والتحديثات.
- توفير لوحة تحكم للموظفين لإدارة الطلبات.
- تطوير Chatbot للإجابة عن الاستفسارات المتعلقة بخدمات المركز.
- توفير لوحات تحليلية ومؤشرات أداء للإدارة.
- تقديم نموذج عملي يوضح إمكانية التحول الرقمي لخدمات المركز.

## 3. نطاق المشروع

يستهدف المشروع بناء منصة تجريبية متكاملة تتكون من المكونات التالية:

### 3.1 بوابة الباحثين (Researcher Portal)

- إنشاء حساب وتسجيل الدخول.
- إدارة الملف الشخصي للباحث.
- استعراض خدمات المركز المتاحة.
- الاطلاع على وصف الخدمات ومتطلباتها.
- تقديم طلبات خدمات تجريبية.
- رفع مستندات تجريبية.
- إنشاء رقم تعريفي فريد لكل طلب (Application ID).
- متابعة حالة الطلب والتحديثات.
- الاطلاع على طلبات المستندات الإضافية والإشعارات.

### 3.2 لوحة تحكم الإدارة (Admin Dashboard)

- تسجيل دخول الموظفين والمديرين وإدارة صلاحياتهم.
- عرض وإدارة طلبات الباحثين.
- البحث عن الطلبات وتصفيتها.
- مراجعة البيانات والمستندات المقدمة.
- تحديث حالات الطلبات.
- طلب مستندات إضافية.
- تسجيل ومراجعة سجل التحديثات.
- إدارة معلومات الخدمات.

### 3.3 المساعد الذكي (Chatbot)

- إعداد قاعدة معرفية (Knowledge Base) بالاعتماد على وثائق المركز المتاحة.
- الإجابة عن الأسئلة المتعلقة بخدمات المركز.
- توضيح متطلبات وإجراءات الخدمات.
- تقديم إرشادات اعتمادًا على الوثائق والمصادر المتاحة.
- دمج المساعد الذكي داخل المنصة.

### 3.4 التحليلات ومؤشرات الأداء (Analytics & KPIs)

- إجمالي عدد الطلبات.
- عدد الطلبات حسب الخدمة.
- عدد الطلبات حسب الحالة.
- الطلبات المكتملة والمعلقة.
- متوسط وقت معالجة الطلبات.
- مؤشرات أداء الخدمات.

### 3.5 الخادم الخلفي وقاعدة البيانات (Backend & Database)

- إدارة مركزية للبيانات.
- إدارة تسجيل الدخول والصلاحيات حسب دور المستخدم.
- إدارة الطلبات والخدمات.
- إدارة المستندات.
- تطوير واجهات برمجية (REST APIs).
- ربط جميع مكونات المنصة.

## 4. القرارات المعتمدة للمشروع

القرارات التالية معتمدة لتنفيذ النموذج التجريبي الحالي:

| البند | القرار المعتمد |
|---|---|
| معمارية المشروع | منصة مستقلة (Standalone Prototype) |
| نطاق المشروع | منصة متكاملة (Full Integrated Platform) |
| طريقة التطوير والتشغيل | تشغيل محلي (Local Development) |
| الميزانية | صفر جنيه (0 EGP) |
| البيانات | بيانات تجريبية مولدة فقط (Synthetic / Generated Data) |
| الدمج المستقبلي | موقع الأكاديمية Joomla/PHP بعد الموافقة |

### ملاحظات مهمة

- ستعمل المنصة في البداية بشكل مستقل.
- لن يتم إجراء أي تعديلات على الموقع الرسمي للأكاديمية خلال المرحلة الحالية.
- لن يتم استخدام بيانات شخصية حقيقية للباحثين.
- ستُستخدم حسابات وطلبات ومستندات تجريبية فقط.
- سيتم تقييم إمكانية الدمج مع Joomla بعد عرض النموذج التجريبي وموافقة الأكاديمية على استكمال هذه الخطوة.

## 5. التقنيات المقترحة

التقنيات التالية مقترحات أولية وليست قرارات نهائية أو إلزامية:

| المكون | التقنية المقترحة |
|---|---|
| الواجهة الأمامية | React |
| الخادم الخلفي | Laravel / PHP |
| قاعدة البيانات | MySQL |
| خدمة المساعد الذكي | Python / FastAPI |
| التواصل بين المكونات | REST APIs |
| إدارة الإصدارات | Git / GitHub |

### سياسة اختيار التقنيات

سيتم تحديد التقنيات النهائية بالتعاون بين أعضاء الفريق، بعد مراجعة:

1. المهارات والخبرات التقنية المتاحة لدى أعضاء الفريق.
2. بيئات التطوير والأجهزة المتاحة.
3. التوافق بين التقنيات المختارة.
4. متطلبات التكامل بين مكونات النظام.
5. توفر الأدوات مجانًا ومفتوحة المصدر.
6. سهولة الصيانة وإمكانية الدمج مستقبلًا مع Joomla.

يحق لأي عضو اقتراح تقنيات بديلة مع توضيح الأسباب التقنية وتأثير الاختيار على بقية أجزاء النظام.

لا تعتبر أي تقنية مقترحة إلزامية إلا بعد مناقشتها واعتماد المجموعة للتقنيات النهائية. ويمكن تحديث هذا الملف والقرارات التقنية مع تطور المشروع.

## 6. سياسة الميزانية الصفرية (Zero-Budget Policy)

هذا المشروع مبادرة تدريبية مجانية، ولذلك يجب أن تتم جميع أنشطة التطوير والعرض دون أي تكلفة مالية على أعضاء الفريق.

- عدم استخدام خدمات استضافة مدفوعة.
- عدم استخدام واجهات برمجية مدفوعة (Paid APIs).
- عدم شراء تراخيص برامج.
- عدم الاشتراك في خدمات ذكاء اصطناعي مدفوعة.
- عدم شراء دومينات.
- تفضيل الأدوات المجانية ومفتوحة المصدر.
- استخدام الخطط المجانية فقط عندما تكون حدودها مناسبة ولا تتطلب أي دفع.

يجب مناقشة أي خدمة قد تترتب عليها تكلفة والحصول على موافقة قبل استخدامها. وقرار التشغيل الحالي هو التطوير والتشغيل المحلي، ولا توجد حاجة إلى استضافة سحابية في هذه المرحلة.

## 10. آلية التعاون على GitHub

لضمان جودة الكود وتجنب تعارض التعديلات:

1. فرع `main` مخصص للنسخة المستقرة من المشروع.
2. يجب تجنب التعديل المباشر على `main`.
3. يعمل كل عضو على فرع (Feature Branch) خاص بالمهمة المسندة إليه.

5. يجب مراجعة التعديلات قبل دمجها.
6. يتولى قائد الفريق تنسيق عملية الدمج النهائي.

## 12. الدمج المستقبلي مع موقع أكاديمية السادات

وفقًا للمعلومات التي تم الحصول عليها من مسؤول موقع الأكاديمية، يستخدم الموقع الحالي نظام Joomla ولغة PHP.

بعد الانتهاء من النموذج التجريبي والحصول على موافقة الأكاديمية على استكمال المشروع، يمكن للفريق بالتعاون مع المسؤول التقني دراسة طرق الدمج المحتملة، مثل:

- تطوير مكون مخصص داخل Joomla (Custom Joomla Component).
- ربط المنصة المستقلة من خلال واجهات API.
- تشغيل المنصة على نطاق فرعي معتمد من الأكاديمية (Subdomain).
- تحديث أو تهيئة بيئة الاستضافة الحالية عند الحاجة.

سيتم تحديد الطريقة النهائية بناءً على إصدارات Joomla وPHP المتاحة، وإمكانيات الاستضافة، ومتطلبات الأمان، وموافقة الأكاديمية.

لا يشمل نطاق النموذج التجريبي الحالي أي دمج مع بيئة الإنتاج أو تعديل الموقع الرسمي.
